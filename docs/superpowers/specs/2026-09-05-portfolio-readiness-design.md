# 双选会项目成熟度设计

日期：2026-09-05。用户授权自主设计、修复、并行对抗审查、项目展示与最终 GitHub 更新。

## 目标与方案

四个仓库应能由陌生读者按说明复现演示，并说明原理、测试、取舍和局限。只润色材料不能消除缺陷；全部重写风险过高；因此采用保留架构、验证驱动修复、补完演示和发布，再重做博客展示的方案。

不把自动测试、模拟器、静态分析冒充实测。审查自有源码、测试、配置、发布入口和现行文档；依赖、缓存、编译产物、二进制和历史方案按清单分类，不虚称逐字人工审查了所有内容。保留用户未提交文件，不读取或发布凭据，不绕过硬件门控。

## 独立设计

### clock / BEID

保留 React、Zustand、Vite、Capacitor、Electron。重点检查持久化与备份、计时与恢复、学习列表与播放器、输入与网络、原生桥和安装包。缺陷用回归用例先复现再修复；用 Vitest、类型检查、生产构建、跨视口流程及可用原生构建验收。B 站 API 和真实设备依赖单列。

### Hardware Butler

保留 nextboard、embeddedskills、tools 边界。验证 CLI、计划执行、安全门、证据报告、GUI、插件镜像和全新安装。提供离线样例，不自动操作真实设备；明确模拟、静态检查、实测的区别，保护 embeddedskills 独立仓库。

### 原生子智能体编排 Skill

维持 Skill 定位，不新增后台、CLI 或模型依赖。逐份核对公开协议、角色、示例与测试。保证只读委派、主模型所有权、不委派即时阻塞任务、失败回收的一致性。此仓库委派只读审查，由主模型修改。

### 博客

保持无构建静态站、hash 路由、旧链接、文章和本地资源。视觉为留白充分、排版鲜明的个人工程作品集；首屏清楚说明方向，项目按问题、实现、证据、边界组织。移动端、明暗主题、键盘和减少动效设置均有效。不新增付费服务、后端或远程字体，不使用未验证数字宣传。

## 文档与发布

每个项目的面试指导书包含 30 秒与 3 分钟介绍、架构数据流、修复案例、取舍、演示、追问、限制、自研和第三方边界。博客与实际代码一致，不编造经历、规模或硬件成绩。

发布前检查差异、许可证、敏感文件、忽略规则、远端和原有变更。仅向已有用户 origin 非强制发布，不修改上游、仓库公开性或凭据。发布结果单独核实，不把本地完成冒充上线。

## 验收

- 有文件范围清单、审查结论、带日期验证命令和结果。
- 阻断缺陷修复，回归和总体检查通过，未验证项如实列出。
- 博客经过桌面与手机截图检查，关键链接和演示可操作。
- README、面试指导书和博客与最终代码一致。
- 不遗漏已有用户文件，不夸大覆盖程度或发布状态。
